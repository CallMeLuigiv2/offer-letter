# Offer Letter — rules for anyone (human or agent) working on this repo

Offer Letter is a desktop app that simulates a software job for one learner
(Luigi): he joins a fictional company, works tickets with AI teammates, and
owns code only after proving he understands it. Design doc:
`DESIGN.html` (published at https://claude.ai/artifact/PR5LQiyiaMQGXWExFMASb7).
Research behind it: `research/` (read `BRIEF.md` first, then the file for
your area). The contract every part builds against: `docs/ARCHITECTURE.md`.
Where things stand: `docs/PROGRESS.md` (the resume point — update it when you
finish something). Decisions: `docs/DECISIONS.md`.

## Who writes what

- The **harness** (server, web app, tools, content kits) is a tool Claude
  writes. Luigi does not write harness code.
- Inside a ticket, the code Luigi must write is **his**. The solution to his
  part never appears in his repos or in the UI, and teammates never write it
  for him; they help with worked examples on a different toy problem. A kit
  may keep a `reference/` fix, used only by `verify_kit.py` to prove the
  hidden grader can pass.
- **Parallel agents:** each agent writes only inside the paths its brief
  gives it, reports in `docs/progress/<agent>.md` (not PROGRESS.md), and
  does **not** run `git commit` (the lead commits, to avoid index races).

## Hard rules

1. **Claude plan only, never API billing.** Teammates run the unmodified
   `claude` CLI headless (`-p`, stream-json), signed in with his claude.ai
   login. Strip `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` and
   `CLAUDE_CODE_USE_*` from the child env. Refuse to run if
   `claude auth status` isn't `authMethod: claude.ai`. **Never pass
   `--bare`** (it ignores the plan login). Never read or copy credential
   files.
2. **Usage.** At most 2 teammate `claude` processes at once. Haiku by
   default; Sonnet for writing/reviewing code; Opus only for design reviews
   and the senior engineer. Every stream-json run emits a
   `rate_limit_event` with `unifiedWindows.five_hour.utilization` (0–1) and
   `resetsAt` (epoch s) — the governor reads that.
3. **Git stays truthful.** Teammate commits use the persona's name with
   " (AI teammate)" and an email at `<persona>@<company>.offerletter.invalid`
   plus a trailer `Offer-Letter-Persona: <id>`. Luigi's commits are his own
   identity. Never rewrite authorship.
4. **Answer keys never reach his repo.** Planted-bug keys, quiz answers and
   hidden grader tests live in the content kit / server data, never in the
   repos he clones.
5. **Licences.** No LimeZu or other non-redistributable art in git. Our
   pixel art is generated by our own scripts (`tools/pixel/`). Excalidraw
   (MIT) not tldraw; Motion (MIT) not GSAP. Pin dependency versions; prefer
   versions at least two weeks old.
6. **No real-desktop driving.** Never synthesize OS input or capture the
   whole screen on this PC (he may be screen-sharing). UI tests run in a
   headless browser (Playwright) and drive the app in-process.
7. **Windows first.** The server runs on Windows with `uv` (Python 3.12).
   Paths via `pathlib`. Shell snippets in docs show PowerShell or Git Bash
   explicitly. Heredocs in Git Bash collapse backslashes — write files with
   the editor tools, not `cat <<EOF`, when they contain `\`.
8. **Tests.** Server: `uv run pytest` in `server/`. Web: `pnpm test` (vitest)
   and `pnpm e2e` (Playwright, headless) in `web/`. Content kits:
   `uv run python tools/verify_kit.py <company>` must pass before a ticket
   ships. A feature is done when its tests pass and PROGRESS.md says so.
9. **Copy.** Plain, direct English from the user's side. No XP, points,
   badges or leaderboards anywhere (decision D1); progress shows as real
   consequences and debriefs.
10. **Commits.** Small, one topic each, message `area: what changed`. End
    with the attribution trailer the session gives you. Don't push anywhere.
